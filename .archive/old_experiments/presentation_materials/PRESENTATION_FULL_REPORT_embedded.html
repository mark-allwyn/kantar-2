Executive Summary

We tested the synthetic survey system against 400 real Czech consumers across 7 question types. Results show construct-specific performance - some question types work, others don't.

  • ✓ WORKS (2/7): Excitement, Relevance

  • ✗ FAILS (4/7): Believability, Uniqueness, Likeability, Value

Methodology Overview

How the System Works

The synthetic survey system uses a three-stage process to simulate human survey responses:

1. Persona Generation

Synthetic respondents are generated with realistic demographics and psychographics including age, gender, occupation, category buyer behavior, brand preferences, and inertia levels. Each persona is screened using the same criteria as human recruitment to ensure comparability.

2. LLM-Powered Response Generation

For each question, a large language model (GPT-4.1) receives:

  • The persona's complete demographic and psychographic profile
  • The product concept description (visual + text)
  • The survey question

The LLM generates a natural language response expressing how that persona would feel about the concept. Temperature is set to 0.5 to balance consistency with realistic variation.

3. Semantic Similarity Rating (SSR)

The LLM's free-text response is converted to a numerical scale rating using semantic similarity:

  • Each scale point has predefined "anchor text" (e.g., "Extremely exciting" for top box, "Not at all exciting" for bottom box)
  • Both the LLM response and anchor texts are converted to high-dimensional embeddings using OpenAI's text-embedding-3-small model (1536 dimensions)
  • Cosine similarity is calculated between the response and each anchor
  • The response is assigned to the closest matching anchor point

Validation Approach

System performance is measured by comparing synthetic responses to ground truth data from 400 real Czech consumers across 8 lottery scratchcard concepts:

  • Accuracy: Mean absolute error and bias between synthetic and human response distributions
  • Consistency: KL Divergence measuring how well synthetic distributions match human distributions (target: KL < 0.20)
  • Correlation: Pearson correlation between concept rankings (target: r > 0.85)

Key Finding

The systematic conservative bias is NOT universal - it's construct-specific. This suggests the issue is in how the LLM interprets different question types, not the SSR methodology itself.

6. The Pattern We Discovered

SSR Works Well For SSR Struggles With
  • Concrete behavioral questions
  • Emotional/feeling-based responses
  • Personal fit assessments ("relevant to me")
  • Questions with clear semantic progressions
  • 4-5 level scales
  • Abstract evaluative judgments
  • Questions requiring cultural/market context
  • Category expertise-dependent assessments
  • Multi-level scales (6+ levels)
  • Trust/credibility judgments

7. What We Learned

From Working Questions

  • Concrete emotional questions are reliable
  • Personal framing ("to me") helps accuracy
  • 4-5 level scales work better than 6+ levels
  • Clear semantic progressions enable good SSR mapping

From Failing Questions

  • Abstract evaluations need cultural anchoring
  • Category expertise can't be easily simulated by LLM
  • Conservative bias specifically affects trust/novelty judgments
  • Distribution shape matters as much as the mean

From The Pattern

  • This is NOT a universal SSR failure
  • This is a construct-specific LLM interpretation issue
  • We can potentially fix with better prompts/context
  • Or we can identify which question types work best with SSR

8. Conclusion

Bottom Line

Good News:

  • SSR methodology works (proven by 2/7 success rate)
  • Clear construct-specific pattern discovered
  • Experimental roadmap is straightforward
  • Can diagnose root cause in 2-3 hours

Challenge:

  • Only 29% of questions work currently
  • Abstract questions need significant improvement
  • Cultural context is harder to simulate than expected

Recommendation:

  • Run diagnostic experiments to understand root cause
  • Then decide on optimization vs question selection approach
  • Don't assume deployment timeline yet - learn first
